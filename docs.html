Manual

Everything PrismTabs does, in the order you'll actually use it. There's nothing to configure to get started — install the plugin and right-click a tab.

Getting started

Install PrismTabs from the JetBrains Marketplace inside your IDE: Settings → Plugins → Marketplace, search "PrismTabs", click Install, then restart the IDE if prompted.

PrismTabs needs no setup beyond installation. The moment it's enabled you can right-click any open editor tab to start colouring it.

Requirement: IntelliJ Platform 2024.2 or newer. See Compatibility for which IDEs that covers.

Assigning a tab to a group

Right-click any editor tab. The first item in the context menu is Tab Group…, which opens the colour swatch popup:

  • Click a preset dot — assigns the tab to a shared, colour-named group (e.g. "Blue"), creating it on first use. This is the fast path: repeated clicks across files on the same colour converge on one group instead of spawning duplicates.
  • Add to Group… — lists your existing named groups; pick one to add the tab to it.
  • New Group… — pick a colour, then name the group. Cancelling the name prompt aborts the whole flow — no group is created.
  • Remove from Group — only shown when the tab is currently assigned; clears the assignment and the tint.

Working with groups

Open Tab Group… on any tab already in a group, then choose Manage Groups… to pick a group and act on it:

  • Rename… — change the group's display name.
  • Recolour… — pick a new preset colour; every member tab repaints immediately.
  • Mark as Active Group / Clear Active Group — see Active groups.
  • Delete Group — asks for confirmation first, then clears the assignment from every member tab (the files themselves are untouched).

You can also manage groups directly from the Tab Groups tool window, which offers the same actions without needing an already-grouped tab to start from.

Active groups

Mark one group active and every file you open afterwards joins it automatically — useful when you're about to dive into a feature and want everything you touch colour-coded without assigning each tab by hand.

The active group doesn't survive a restart, by design. An assignment is something you explicitly chose; "active" is closer to a recording toggle you'd likely forget was on. Restarting the IDE always clears it, so files never get auto-coloured for a reason you can no longer see. Groups marked active are labelled (active) wherever they appear in the popup.

The Tab Groups tool window

Open the Tab Groups stripe on the right-hand edge of the IDE window (or find it under View → Tool Windows → Tab Groups). It lists every group with its colour dot, name, member count, and whether it's collapsed. A toolbar and matching right-click context menu offer Collapse/Expand, Rename…, Recolour…, and Delete Group for the selected group.

This panel exists because IntelliJ has no public API for an in-strip spanning colour label the way Chrome has — reproducing that would mean custom-painting an internal, unstable part of the tab strip. The tool window is the deliberate substitute: everything a group needs to be managed lives in one place instead.

The list updates live — a group created from the swatch popup on another tab shows up here immediately, no need to reopen the panel.

Collapsing & expanding

PrismTabs has no way to visually shrink a group into a chip the way Chrome does — the platform doesn't expose one. Instead, collapse means "close and remember":

  • Collapse closes every open tab belonging to the group and records exactly which files were open, in order.
  • Expand reopens each of those files, in the same order, without changing focus away from what you're already looking at.

Use it to get a crowded group out of the way without losing track of what was open in it — the group stays listed in the tool window (marked "collapsed") the whole time.

To change a preset's name or colours, open Settings → Tools → PrismTabs. Each row has an editable name field and a colour picker for the light and dark variant. Changes apply immediately to every group using that preset; a Restore Defaults link resets everything back to the built-in palette in one step.

This is an IDE-level preference, not a per-project setting — it follows you the same way an editor colour scheme would, across every project you open.

Persistence & renames

Group assignments and collapsed state are stored per-project and survive an IDE restart. They also follow a file through a rename or a move, including files nested inside a renamed or moved directory — you won't lose a tab's colour just because you reorganised your project.

Compatibility

PrismTabs depends only on com.intellij.modules.platform, so it isn't tied to one product — it runs in IntelliJ IDEA, WebStorm, PyCharm, GoLand, PhpStorm, Rider, RubyMine, CLion, DataGrip, Android Studio, and any other IDE built on the same platform, from 2024.2 onward. It's tested against both the classic and Islands tab painters, and against light, dark, and high-contrast themes.

FAQ

Why does an unselected tab look more faded than the selected one?

IntelliJ's own tab painter blends unselected tab colours to roughly half strength against the background — that's a platform behaviour, not something PrismTabs can override. The palette's dark presets are deliberately saturated enough to stay clearly visible even after that blend.

Does a colour follow the tab or the file?

The file. If the same file is open in two split editors, both tabs show the same colour — the platform's colour API is keyed on the file, not on an individual tab instance.

Can I get a Chrome-style bar that spans several grouped tabs?

Not currently — IntelliJ has no public API for it, and building one would mean custom-painting an internal, unstable part of the platform. The Tab Groups tool window is the supported way to see and manage a group as a unit.

Can tab text colour change along with the background?

No. The relevant platform API for tab foreground colour is experimental and tied to file status, not to PrismTabs' groups, so only the tab background is themeable.

What happens to a group's files when I delete the group?

Only the assignment is removed — every member tab loses its colour and its group membership, but the files themselves are completely unaffected. Deleting a group always asks for confirmation first.
